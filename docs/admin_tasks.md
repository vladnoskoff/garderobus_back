# Мониторинг задач Celery и AI

В проекте есть два уровня просмотра задач:

1. **Публичный статус конкретной задачи** — без авторизации для GET-запросов, подходит для мобильных/виджетов.
2. **Админка** — полный список запусков с прогрессом, ошибками и логами.

## Публичный статус задачи
- **Endpoint:** `GET /ai/tasks/{task_id}`
- **Что отдаёт:** текущее состояние (`pending`/`started`/`success`/`failure`), прогресс `0..100`, ошибка (если есть) и дополнительные метаданные.
- **Как получить `task_id`:** он возвращается в ответах на запуск генерации, например `/ai/mannequin/{user_id}`.
- **Требования к auth:** для метода `GET` авторизация не требуется (можно опрашивать клиентом напрямую).

## Административный просмотр истории
Все админ-эндпоинты требуют авторизации админа (Bearer токен).

### Где это увидеть в админке
- **Список и детали запусков:** админ-панель обращается к тем же маршрутам `GET /admin/system/tasks` и `GET /admin/system/tasks/{task_id}`. Откройте раздел **System → Tasks** (или аналогичный пункт меню) — там отображаются истории запусков, прогресс и ошибки.
- **Живая очередь:** раздел **System → Queue** использует `GET /admin/system/queue` и показывает активные/отложенные задачи и состояние брокера.
- **Права:** для обоих разделов нужен валидный Bearer-токен администратора (тот же, что используется для вызова API напрямую).

### Список всех запусков
- **Endpoint:** `GET /admin/system/tasks`
- **Параметры:**
  - `status` — фильтр по статусу (`pending`, `started`, `success`, `failure`).
  - `name` — фильтр по имени задачи (совпадает с Celery task name).
  - `limit`, `page` — пагинация (по умолчанию `limit=25`, `page=1`).
- **Что отдаёт:** массив `tasks` с каждым запуском, включая id, имя, статус, `progress`, текст ошибки и `log_excerpt`, а также счетчики `total`, `page`, `limit`.

### Детали конкретного запуска
- **Endpoint:** `GET /admin/system/tasks/{task_id}`
- **Что отдаёт:** все поля записи (`status`, `progress`, `error_message`, `log_excerpt`, временные метки `created_at` / `started_at` / `finished_at`, `meta`).

### Снимок живой очереди
- **Endpoint:** `GET /admin/system/queue`
- **Что отдаёт:** текущее состояние очередей Celery (active/reserved/scheduled), список задач «в полёте» и флаг доступности брокера.

## Типичные сценарии
- **Пользовательский клиент** запрашивает `/ai/tasks/{task_id}` раз в несколько секунд, чтобы показать прогресс генерации и возможные ошибки.
- **Администратор** смотрит `/admin/system/tasks` для истории и диагностик, при необходимости открывает `/admin/system/tasks/{task_id}` чтобы увидеть лог или исключение по конкретному запуску, или `/admin/system/queue` чтобы понять загрузку воркеров.
